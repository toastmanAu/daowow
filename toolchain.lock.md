# toolchain.lock.md — DAOWOW reproducible toolchain

Recorded: 2026-09-05 (first implementation sprint)

## Rust

| Component | Version |
|---|---|
| rustc / cargo (host + cross) | 1.98.1 (48a229cea 2026-09-01) |
| Toolchain channel | pinned in `rust-toolchain.toml` (`1.98.1`, minimal profile, rustfmt + clippy) |
| RISC-V target | `riscv64imac-unknown-none-elf` (rustup target, same 1.98.1) |

Install: `rustup` from <https://sh.rustup.rs>; `rustup target add riscv64imac-unknown-none-elf`.
A native `cc` (gcc 13.3.0, Ubuntu 24.04 build-essential) is required for host builds
(`cc` crate); CKB contracts themselves compile pure-Rust (no C, no clang needed
because the ckb-std `libc`/`dlopen-c` features are disabled).

## Contract build flags (`.cargo/config.toml`, riscv64 target)

```text
--cfg daowow_noatomic            # selects vendored bytes' non-atomic refcounts
-C link-arg=--no-rosegment       # required: without it .rodata shares an executable
                                 # page and ckb-vm faults at startup
                                 # (MemWriteOnExecutablePage)
```

Deliberately NOT used: `-C target-feature=+zba,+zbb,+zbc,+zbs` /
`-C passes=lower-atomic` (the cryptape template defaults). On rustc 1.98.1 the
`lower-atomic` LLVM pass no longer exists, so emitted B-extension instructions
would fault on the VM's ISA_IMC (data-hash-type scripts run VM V0 = IMC only).

## Script deployment convention

Contracts are plain `bin` crates (no_main + `ckb_std::entry!`), deployed with
**hash_type `data1` (0x2)**. `data1` selects VM V1 (IMC | B | MOP) in
ckb-script 1.2.0; `data` would select V0 (IMC only). Binaries are produced by:

```sh
cargo build --target riscv64imac-unknown-none-elf --release -p <contract>
# artifact: target/riscv64imac-unknown-none-elf/release/<contract>
```

## Test oracle

`ckb-standalone-debugger` v1.1.1 (x86_64 release binary) cross-checks failing
transactions from `ckb-testtool` `Context::dump_tx` JSON. On this toolchain the
debugger (VM V1) and testtool agree once scripts are deployed as `data1`.
