# Gates 3b and 3c Implementation Plan — the draw, and settlement

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seal a closed round, finalise its chain entropy, compute the draw, and
drive the DAO and settlement to a paid-out round.

**Architecture:** Pure JavaScript builders emitting unsigned ckb-cli tx files,
plus a checker re-deriving every rule from the finished bytes. Codecs pinned
byte-for-byte to Rust-generated vectors. No process holds a key.

**Tech Stack:** Node (no build step), the vendored CCC bundle, `node:test`,
`ckb-cli` for signing, Rust `gen_vectors` for oracles, the isolated Docker
devnet for 3c.

**Spec:** `docs/superpowers/specs/2026-10-01-gate-3bc-design.md`

## Global Constraints

- **Two tracks.** 3b runs on public testnet against round `0xa42e2888…` and
  starts the real 180-epoch clock. 3c is developed on devnet, where 180 epochs
  costs ~2,500 generated blocks. **Nothing in 3c counts as proving the
  protocol** — `tests/devnet/test_round_creation.py` already does — it proves
  the TOOLING.
- **The entropy `since` is a RELATIVE BLOCK NUMBER**, not an epoch: top byte
  exactly `0x80`, low bits ≥ 256 (`entropy.rs:52`). Every other `since` in this
  protocol is an absolute epoch with `0x20`. Using the familiar form fails as
  `SHARD_ERROR_STATE` with no mention of metrics.
- **Exactly four header deps on the entropy transaction**, in order: the seal's
  inclusion block, then +64, +128, +192. A fifth is REFUSED.
- **The DAO `since` is measured from the DEPOSIT**, not the withdrawal. This is
  recorded as a live bug in `ckb-transactions.feedback.md` (2026-06-16).
- **DAO phase one is index-for-index**: for the input at absolute index `i`,
  output `i` must keep the same capacity, type and lock. A builder that appends
  outputs gets this wrong.
- **No key material.** Builders emit unsigned transactions; Phill signs.
- **`--skip-check` on BOTH `tx sign-inputs` and `tx send`** for anything
  carrying a public-lock cell; without it ckb-cli refuses to sign and leaves an
  empty witness.
- **Every input's lock needs a cell dep**, `sponsor.lockDep` included, via
  `tools/lock-deps.mjs`.
- **Ported rules cite their Rust line** and are tested against a Rust-generated
  vector, never against our own output.
- **A guard is not pinned until a mutation reds its own named test, alone.**
  Run the probe harness with its `node --check` step and its explicit NOT
  PINNED report.
- Commit messages end with `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`.

### Task 2: The seal and entropy codecs

**Files:**
- Create: `apps/web/chain/seal-codec.js`
- Test: `apps/web/test/seal-codec.test.js`

**Interfaces:**
- Consumes: `ledger-codec.js` for the embedded `AggregationState`.
- Produces: `decodeRoundSeal(bytes, shardCount)`, `encodeRoundSeal(seal)`,
  `decodeEntropyRecord(bytes, shardCount)`, `encodeEntropyRecord(record)`,
  `sealSize(shardCount)`, `recordSize(shardCount)`, `SEAL_VERSION = 3`,
  `RECORD_VERSION = 4`.

Layouts, from `seal.rs`. `RoundSeal`: `u8 3 | u32 LE shard count | count ×
207-byte ledgers` — `5 + 207 × shards`, so **212 bytes at one shard**.
`EntropyRecord`: `u8 4 | seal bytes | u64 LE inclusion height | 32-byte
inclusion hash | 3 × 32-byte entropy hashes` — `1 + sealSize + 136`, so **349
bytes at one shard**. The seal bytes carry their own leading `3`, so the record
holds TWO version bytes; an earlier draft said 348 by missing one, and the Task 1
vector caught it.

- [ ] **Step 1: Write the failing size and round-trip tests**

```js
test("the sizes follow the shard count", () => {
  assert.strictEqual(sealSize(1), 212);
  assert.strictEqual(recordSize(1), 349);   // TWO version bytes: 4, then the seal's 3
  assert.strictEqual(sealSize(2), 419);
});

test("the seal round-trips the Rust oracle", () => {
  const o = V.round_seal;
  assert.strictEqual(hex(encodeRoundSeal(decodeRoundSeal(unhex(o.hex), 1))), o.hex);
});

test("the record round-trips, and its embedded seal decodes too", () => {
  const r = decodeEntropyRecord(unhex(V.entropy_record.hex), 1);
  assert.strictEqual(hex(encodeEntropyRecord(r)), V.entropy_record.hex);
  assert.strictEqual(r.inclusionHeight, BigInt(V.entropy_record.inclusion_height));
  assert.strictEqual(r.seal.ledgers.length, 1);
  assert.strictEqual(r.seal.ledgers[0].closed, true, "a seal only takes closed ledgers");
});
```

- [ ] **Step 2: Run them and watch them fail**

- [ ] **Step 3: Implement, IIFE-wrapped, resolving siblings LAZILY**

Do not destructure `ledger-codec` at load. `discovery.js` did exactly that and
took out `entry.html` silently — a module that throws inside its IIFE publishes
nothing and the symptom surfaces elsewhere as a missing function.

- [ ] **Step 4: Pin each field, and each refusal on its own message**

Assert every field against the vector individually; a round trip passes with

### Task 4: The entropy transaction

The sharpest task in the plan. Two rules here have no precedent elsewhere in
the protocol.

**Files:**
- Create: `apps/web/chain/entropy-tx.js`
- Test: `apps/web/test/entropy-tx.test.js`

**Interfaces:**
- Produces: `entropyHeights(inclusionHeight) -> [h64, h128, h192, h256]`,
  `relativeBlockSince(blocks) -> BigInt`, `buildEntropyTx({manifest, config,
  sealCell, inclusionHeader, entropyHeaders, configCellOutPoint, sponsor})
  -> {tx, expectedRecord, earliestHeight, fee}`,
  `RELATIVE_BLOCK_FLAG = 0x8000000000000000n`.

- [ ] **Step 1: Write the failing tests, starting with the two unprecedented rules**

```js
test("entropyHeights is inclusion plus 64, 128, 192 and 256", () => {
  assert.deepStrictEqual(entropyHeights(1000n), [1064n, 1128n, 1192n, 1256n]);
  for (const v of V.entropy_heights) {
    assert.deepStrictEqual(entropyHeights(BigInt(v.inclusion)),
      v.heights.map(BigInt));
  }
});

test("the since is a RELATIVE BLOCK NUMBER, not an absolute epoch", () => {
  // entropy.rs:52 requires `since >> 56 == 0x80`. Every other since in this
  // protocol is an absolute epoch with 0x20, and using that form fails as
  // SHARD_ERROR_STATE with no mention of metrics. This is THE trap of 3b.
  const { tx } = buildEntropyTx(base());
  assert.strictEqual(tx.inputs[0].since >> 56n, 0x80n);
  assert.notStrictEqual(tx.inputs[0].since >> 56n, 0x20n);
});

test("the relative block count is at least 256", () => {
  assert.ok((buildEntropyTx(base()).tx.inputs[0].since & 0x00ffffffffffffffn) >= 256n);
  assert.throws(() => relativeBlockSince(255n), /256/);
});

test("there are EXACTLY four header deps, in order", () => {
  // A fifth is refused outright (entropy.rs:72 requires IndexOutOfBound at 4).
  const { tx } = buildEntropyTx(base());
  assert.strictEqual(tx.headerDeps.length, 4);
  assert.strictEqual(tx.headerDeps[0], inclusionHeader.hash, "dep 0 is the seal's own block");
  assert.deepStrictEqual(tx.headerDeps.slice(1), entropyHeaders.map((h) => h.hash));
});

test("a header at the wrong height is refused before signing", () => {
  const wrong = [{ ...entropyHeaders[0], number: "0x999" }, ...entropyHeaders.slice(1)];
  assert.throws(() => buildEntropyTx({ ...base(), entropyHeaders: wrong }),
    /\+64|height/);
});

test("the record is what the contract will recompute", () => {
  const { tx } = buildEntropyTx(base());
  assert.strictEqual(tx.outputsData[0].replace(/^0x/, ""), V.entropy_record.hex);
});

test("earliestHeight says when this transaction becomes sendable", () => {
  // Not decoration: a keeper needs to know it is a ~34 minute wait, not a
  // failure, and the dry run prints it.
  const { earliestHeight } = buildEntropyTx(base());
  assert.strictEqual(earliestHeight, BigInt(inclusionHeader.number) + 256n);
});

test("the record cell clears its 460 CKB floor, a 137 CKB top-up over the seal", () => {
  // NOT in the plan as first written: the record holds 349 bytes against the
  // seal's 212, so this step grows its cell more than genesis and seal combined.
  const { tx, topUp } = buildEntropyTx(base());
  assert.ok(BigInt(tx.outputs[0].capacity) >= 460n * CKB);
  assert.strictEqual(topUp, 137n * CKB);
});

test("a seal input whose data is not a seal is refused", () => {
  // entropy.rs:31 — before[0] must be 3.
  assert.throws(() => buildEntropyTx({ ...base(), sealCell: { ...sealCell, data: ledgerBytes } }),
    /seal/i);
});
```

- [ ] **Step 2: Run them and watch them fail**

- [ ] **Step 3: Implement**

`relativeBlockSince(256n)` is `0x8000000000000100n`. Build the header deps from
the supplied headers rather than computing hashes locally — a header hash is
the node's to report.

- [ ] **Step 4: Mutation-check, with extra care on the two unprecedented rules**

Probe the `0x80` flag, the ≥256 bound, the header count, and each header's
height check SEPARATELY. The flag and the bound live in one `if` in the
contract; keep them as two guards here so each can be pinned.
