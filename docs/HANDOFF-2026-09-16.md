## What exists on chain now

**Claim cell** (one per ticket, minted inside the entry append transaction)

- lock: the holder's wallet lock
- type: `entry-shard-type` code hash, args `[5] ‖ config_commitment(32) ‖ shard_id(u32 LE) ‖ position(u64 LE)` (45 bytes)
- data: `PrizeRedemptionState` (81 bytes): version 1, ticket id, paid-set SMT root, paid count, paid total
- occupied capacity: 200 CKB with an argless lock, 220 CKB with secp256k1; returned at retirement (sub-project 3)

**Claim script modes** (`contracts/entry-shard-type/src/claim.rs`)

- mint: no group input; requires an OPEN shard of the same identity as input and output (the shard append counts claims: exactly one per new ticket, locked to the entrant, fresh state)
- transfer: one in, one out, byte-identical data, any lock
- redeem: data differs; exactly one settlement funding input of this commitment must name this claim in its redemption witness; output state must equal `record_verified_prize(prize_source, amount, absence_proof)`; lock unchanged
- burn (input, no output): rejected (`CLAIM_ERROR_RETIRE`) until sub-project 3

**Funding cell v3** (`SettlementFundingDataV3`, 160 bytes): the eight V2 fields
plus `prize_count`, `prize_root` (MMR over `prize_leaf(ticket, amount)` sorted
by ticket id) and `prize_paid`. Created by DAO phase two exactly as before, but
`InitialEntitlements::derive` now credits prizes to ticket ids and principal
only to depositors. Winner ownership proofs no longer exist; the phase-two
witness is version 2.

**Settlement modes** (`contracts/settlement-type/src/main.rs`)

- payout (witness first byte is a count): unchanged principal path, except a
  non-final payout may now reach the last liability while prizes are
  outstanding, and a final drain requires prizes complete
- redemption (witness first byte `0xFF`): up to 32 items, each proving
  `prize_leaf(ticket_from_claim_args, amount)` at `prize_index`, paying the
  claim's current lock, requiring the claim successor's counters to advance by
  exactly that item; `prize_paid` grows by the sum; conservation as for payouts
- final drain on either path: `payout_cursor == liability_count` and
  (`prize_count == 0` or `prize_paid == prize_pool`)

**Error codes** (`crates/daowow-core/src/error.rs`): `SHARD_ERROR_CLAIM_CELL -38`,
`SETTLE_ERROR_REDEEM -77`, `CLAIM_ERROR_ARGS -91`, `_DATA -92`, `_GROUP -93`,
`_MINT -94`, `_TRANSITION -95`, `_RETIRE -96`, `_REDEEM -97`.

**Pure core** (`crates/daowow-core/src/`): `claim.rs` (args, initial state,
`validate_mint`, `validate_transfer`, `claim_occupied_capacity`),
`redemption.rs` (`prize_source`, obligation key, payment leaf,
`PrizeRedemptionState`), `leaf.rs::prize_leaf`, `computed_draw.rs::locate`,
`entitlements.rs` (`PrizeEntitlement`, `prizes()`), `witness.rs`
(`RedemptionItem`, `encode/decode_redemption_witness`,
`MAX_REDEMPTION_ITEMS = 32`, `MAX_REDEMPTION_WITNESS_BYTES = 128 KiB`).

## How to build and test

```bash
# contracts: build each package separately (the workspace has std crates)
for c in round-type entry-shard-type entry-lock dao-lock settlement-type accumulator-bench smoke-alloc smoke-minimal; do
  cargo build --target riscv64imac-unknown-none-elf --release -p $c
done
cargo test -p daowow-core --lib                          # 124 tests
cargo check -p daowow-core --no-default-features         # no_std
cargo clippy -p daowow-core --lib -- -D warnings
cargo test -p daowow-core --test gen_vectors             # rewrites tests/vectors/daowow_core_vectors.json
cd tests/integration && cargo test --no-fail-fast        # smoke has 2 pre-existing failures, ignore them
# isolated Docker devnet (about 21 minutes; do NOT rebuild any contract while it runs)
cargo build -p daowow-integration-tests --examples
DAOWOW_RUN_ISOLATED_NODE=1 python3 -m unittest discover -s tests/devnet -v
```

After `gen_vectors`, regenerate `apps/web/vectors.js` with the Python snippet
in `apps/web/PROGRESS.md`; the web checks are `node apps/web/test/*.test.js`.

## Traps learned the hard way (all recorded in `~/.claude/rules/ckb-transactions.feedback.md`)

- `ckb-testtool`: never re-verify a transaction after `chain_cell` advanced its
  input; the script sees before == after. Return cycles from the helper.
- CKB executes script groups in script-hash order, not input order. When two
  scripts both reject, the reported code is hash luck. To pin a guard in
  script A, keep script B consistent (recompute its expected state).
- A rejection test that pairs a forged cell with garbage decoy data pins
  nothing; use a decodably valid decoy so only the guard under test can refuse.
  Then prove it by mutation: remove the guard, the named test must go red.
- Occupied capacity of a script is `33 + args.len()`, not the molecule
  `as_slice().len()` (which carries a 16 to 20 byte header).
- Cell floors bind transaction order: a funding successor must keep about
  307 CKB and a payment cell 47 to 61 CKB. Small prize pools must be redeemed
  before the principal drain, and sub-floor prizes need a sponsor top-up the
  contract tolerates but does not count.
- Wire bounds must be checked jointly against the 512 KiB never-freed script
  heap; per-field caps alone let a valid witness abort the VM.
- Two-script validation splits need the paying script to verify the
  counterparty's state advanced by exactly the item, not merely that a
  successor exists (an unchanged successor passed the claim script as a
  transfer while the settlement paid).
- Do not rebuild contract binaries while the devnet suite runs; each test
  deploys the binaries fresh.

## Sub-project 3: retirement and winner memento (next)

Scope from the lifecycle design and the amendment:

- Retire a claim (consume without successor) only with proof that every prize
  obligation is discharged. Under the current draw every winner is owed from
  every batch of the round, so the obligation universe for a ticket is either
  none (not a winner) or all batches in the sealed round. Both are provable
  from cell deps: the entropy record (draw positions via `ComputedDraw`) and
  the seal (batch count per shard via `AggregationState::accepted_batches`).
  A non-winner retires immediately; a winner retires when `paid_count` equals
  the batch count and, ideally, the paid set contains every batch's source
  (membership proofs per source, or accept the count given sources are unique
  per key). Failed rounds: no prizes, every claim retires after the seal.
- Final winning redemption (or retirement of a winner) atomically issues a
  non-financial winner memento cell: distinct type identity, no claim or
  remint authority, procedurally unique from the ticket identity and a
  committed template version. Templates are `ticketBlank.png` and
  `ticketWinner.png` in the repo root (hashes in the amendment). Prevent
  duplicate issuance.
- Claim capacity returns to the holder at retirement; memento capacity is the
  holder's own cost.
- Decisions to take before writing the spec: whether retirement is a claim-only
  transaction with cell deps (recommended) or must ride the last redemption;
  whether the memento is a new mode of `entry-shard-type` (consistent with the
  claim) or a separate script; what the memento's data layout commits to
  (ticket id, template version, render seed).

Suggested plan shape, mirroring sub-projects 1 and 2: core obligation-universe
helper with host tests, claim retire mode with cell-dep authentication,
memento mode, VM suites (accepted: non-winner retire, winner retire after all
batches, memento issued once; rejected: premature retire, retire with unpaid
batch, duplicate memento, memento used as a claim), devnet extension, review,
mutation probes, results.

## Other open items

- Unclaimed prizes leave a funding cell open indefinitely (decided for the
  beta); an expiry sweep would need a config field and a since-gated mode.
- `entry-shard-type` scans all outputs twice per append (claim collection and
  entry matching) and the settlement's successor search is O(items x outputs);
  a single-pass scan is a cost follow-up, not a correctness issue.
- The web entry quote does not show claim capacity yet
  (`claim_occupied_capacity(33 + lock_args_len)`); `apps/web/engine.js` still
  simulates prizes paid to participants.
- `beta-rule-enforcement-audit.md` items (round-wide cap, per-lock cap, entry
  opening/closing enforcement) are unchanged by this work.
- Deployment manifest is still `prototype-code-cells-only`; the testnet code
  cells predate all of this and must be redeployed before any funded round.
